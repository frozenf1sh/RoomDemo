# 海画涌现演出样片

目标是让玩家只组合「海 + 画」，随后看见水进入现实，旧植物与窗外自行回应。领域规则和发现条件保持原样；演出节奏只存在于 Unity 表现层。

## 基线

- 2026-10-04：编译、34 项编辑模式测试、9 项运行模式测试、场景校验与 macOS 构建通过。
- 初始独立试玩截图见 `基线_初始房间.png`；领域涌现预设截图见 `基线_涌现与性能.png`。
- 基线现象：海画、水滴、水生植物和海窗几乎同时开始变化，难以读出扩散因果。
- 编辑器运行模式，844 × 451，5 秒采样：平均 60.1 帧/秒，帧时间第 99 百分位约 19.9 毫秒，发生 5 次第零代回收。这个结果包含编辑器开销，不能用于宣称独立程序或普通 PC 性能。
- 离线机位截图用于比较空间摆放，编辑模式下可同时看见多个状态层；它不代表新游戏状态。

## 当前构图与光照

- 桌椅退到右侧，画框底部的滴水路径与落点保持可见。
- 盆栽、画、窗户保留独立视觉空间，固定观察机位仍允许玩家自由转头。
- 光照脚本分为暖灰初始、远方自然光、局部海光与涌现终态。海光只通过表现进度扩大。
- 场景增量工具拒绝覆盖未保存的调整，保留原有 Prefab 身份与稳定 ID。

## 真人评审

最终样片必须由至少一名未参与实现的人试玩，不能用自动测试代替。

1. 从「海的解释之前」开始，执行「海 + 画」，观察画、水、植物、窗外四个独立节拍。
2. 不提前讲解原因，询问「你觉得植物为什么后来变了？」。
3. 询问「刚才哪些变化是你直接做的，哪些不是？」。
4. 记录是否注意到第一滴水、植物性质变化和窗外变化，以及是否感到意义正在扩散。

真人理解度与 60～90 秒观察段的情绪曲线目前待验收；自动化只验证功能、时序和恢复。

## 笔记本与开发入口

笔记本保留点击选择与三槽输入，纸页与墨迹只改变输入表现；失败不消费碎片。新发现提示和按钮未读闪烁继续保留。

- `N`：打开笔记本。
- `F3`：领域事实与预设。
- `F4`：独立演出预览、重置预览、预览终态、恢复真实事实。
- `F6`：进入「海的解释之前」，随后在笔记本手动组合海与画。
- `F8`：将独立程序切换到 1440 × 900 窗口，便于实际程序评审。

真实 macOS 构建已经用鼠标完成一次海画组合与连续演出走查。发现并修正顶部栏缩小造成按钮中文文字裁切，新增实际布局行高测试；新增正式解释接管调试预览的生命周期测试。陌生玩家对因果的理解尚未代替验证。

## 环境布置与原生复测

已补充顶面、画架落地支撑、窗帘、失败画布、干颜料、画笔、旧杯子和揉皱的纸。装饰没有游戏实体或调查碰撞；核心物体仍只有五个。桌上风纸已跟随桌子位置，湿痕局限于画框到植物之间，不把整个地面染蓝。原始纹理的过强颗粒已降低。

灰盒生成保护检查见 `场景保护验证.json`：154 个原有内容文件的 SHA-256 在生成独立灰盒前后保持一致。新增灰盒使用单独材质、音频、Prefab 与场景目录。

原生 macOS 构建的十轮技术复测已全部通过，完整报告见 `原生十轮复测.json`。每轮通过正式 Notebook API 提交海画配方；所有轮次最终得到 11 个事实、8 个反应、3 个已完成配方，四个主表现与最终氛围进度均到位。

最终无截图取样环境：Apple M5、1440 × 900、60 帧目标，原生 macOS 程序；Editor 打开但保持空闲，未并行运行测试。10/10 轮通过，平均 59.3～59.5 帧/秒，第 99 百分位约 17.6～19.9 毫秒；采样内第零代回收为 0。首轮最大帧时间仍为 44.2 毫秒，后续轮次最大约 20.4～33.0 毫秒，因此仍保留首次使用尖峰的风险。完整逐帧数据见 `原生十轮复测.json`，简表见 `原生复测汇总.json`。

优化前首轮曾在滴水附近出现 182.2 毫秒和 50.2 毫秒的尖峰，原始历史记录保留在 `湿痕优化前复测.json`。之后湿痕从通用透明 Lit 改为专用薄湿痕 Shader，新的本机首次启动最大值为 44.2 毫秒。这是实际开发机观察结果，不能排除驱动缓存、系统调度等因素，也不能推断普通 PC 表现。两组测试都在 macOS 锁屏期间运行；优化前最后两轮还存在 Editor 验证流水线后台活动。
F9 启动十轮复测，F10 取样一轮；输出位于 Unity 用户数据目录的 `BenchmarkReview`。原生程序也支持 README 中的 `-roomDemoReview` / `-roomDemoCapture` 参数。十轮结果只证明功能稳定性，不证明真人因果理解或最终美术品质。

最终流水线再次通过 34 项编辑模式测试、14 项运行模式测试、场景验证和 macOS 构建，0 个构建错误、3 条既有包级提示；完整结果见 `最终流水线验证.json`。原生日志还显示部分 URP 景深／投影后处理 Shader 被裁剪，相关后处理不执行，本段未依赖这些效果。Editor 日志中的 Unity 云端符号上传服务还曾报告缺少 dSYM，但构建报告为成功、0 个构建错误。没有为绕过这些服务消息覆盖原有渲染或云设置。
