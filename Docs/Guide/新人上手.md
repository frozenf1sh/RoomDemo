## 打开项目

1. 用 Unity Hub 打开仓库根目录，版本使用 `ProjectSettings/ProjectVersion.txt` 中记录的版本。
2. 当前可玩副本的开发场景是 `Assets/_Game/Content/Scenes/AtelierPlayable.unity`，场景已纳入 Git。正式美术基线是 `AtelierNight.unity`。
3. Build Settings 当前只启用 `AtelierNight.unity`。开发场景和构建入口职责不同，不要为了运行开发场景改构建列表。
4. 导入完成后看一遍 `git status --short --branch`，确认工作区已有内容再开始编辑。

## 关键系统怎么改

本次四阶段改造先读[交付入口](../Design/全流程重设计20261019/README.md)和[分工联调协议](<../Design/全流程重设计20261019/10 分工排期与联调协议.md>)。UI同学在`codex/atelier-four-stage-ui`开发独立UI预览与母版，主场景和流程由冻鱼与Codex负责。现有场景的71个Prefab拆分和五项独立TA已落地；TA方向已人工确认通过，主分支线正在实现首批P00至P07。当前实际范围、操作和UI真实接口见[12 主流程首批实施记录](<../Design/全流程重设计20261019/12 主流程首批实施记录.md>)，二至四阶段与双路线仍待后续批次。最新开场、UI分支共同基线、笔记笔刷/词条提示/首次导读的分工见[13 修订](<../Design/全流程重设计20261019/13 第一阶段优化与UI接手基线.md>)。

| 系统 | 位置 | 使用方法 |
|---|---|---|
| 世界事实与规则 | `Runtime/Domain/State/GameState.cs`、`Engine/RuleEngine.cs`、`Rules/` | 在对应规则表中增加稳定 ID、发现条件、配方或反应。不要把场景名和动画条件塞进通用引擎。 |
| 会话与用例 | `Runtime/Application/GameSession/` | Unity 通过 `Inspect`、`ObserveDetail`、`Combine`、`PerformAction`、`AdvanceDay` 发命令；读取事件更新表现。不要从 UI 直接改状态。 |
| 交互与笔记本 | `Runtime/Unity/Interaction/`、`UI/NotebookView.cs`、`UI/NotebookCanvasView.cs` | 在场景中配置交互目标；笔记本只管临时选词和提交。新增线索或配方时同步检查显示名与中文布局。 |
| 四阶段首批开场 | `Runtime/Domain/AtelierFlow/`、`Runtime/Unity/ArtRebuild/FourStage/` | `AtelierFlowGameplay`装配首批新会话，真实作品保存在`GameState.AtelierCanvas`，输入通过GameSession提交。旧AtelierGameplay与静物Presenter已在新装配停用。 |
| 旁白与世界表现 | `Runtime/Unity/Narrative/`、`Presentation/` | 旁白文本和触发条件集中维护；世界状态变化由 Presenter 响应领域事件，演出只控制时间、画面和声音。 |
| 技术美术 | `Runtime/Unity/TechnicalArt/RealtimePainterly/`、`Content/TechnicalArt/Production/Prefabs/` | 生产 Renderer、天空、水面和擦开效果见[接入说明](../TechnicalArt/Production/接入说明.md)。这些组件只负责表现。 |
| 场景与资源生成 | `Assets/_Game/Editor/` | 使用现有 Builder 和 Unity Editor API。不要在文本编辑器里手改 Scene、Prefab YAML；移动资源时连同 `.meta` 一起处理。 |

## 验证

- 改 Domain/Application：运行对应 EditMode 或 PlayMode 测试。
- 改场景、材质、Shader、VFX 或动画：编译、运行当前场景并检查 Console；不跑旧归档流水线代替现场检查。
- 中文或 UI 改动：在实际构建中检查字形、换行和小窗口布局。
- 具体边界见仓库根目录 `AGENTS.md`。
