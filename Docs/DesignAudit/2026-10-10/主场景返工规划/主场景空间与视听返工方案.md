# 主场景空间与视听返工方案

规划日期：2026-10-10  
目标场景：后续重新搭建的独立主场景；具体路径由实施者建立时确定。  
状态：方案交接。阶段01灰盒已被用户否决并删除；本文件后续段落是实施建议，不代表已经完成。

## 交接硬约束

1. **五张 AI 概念图只用于构图、色彩、材质和氛围参考。绝对禁止把它们作为游戏中的天空、Skybox、模型贴图、墙/画布贴图、Billboard、Decal 或图集；也不得裁剪概念图局部充当贴图。** 概念图留在 `Docs/`。
2. **用户喜欢的是流动的程序化星空。屋顶中央大面积显露必须由运行时程序化绘画/星空 Shader 表现，持续可见流动；不得以任何静态星空图片替代。** 现有实现入口优先核对 `Assets/_Game/Content/TechnicalArt/Production/Shaders/LivingSkySurface.shader`、`ApprovedSkyPaint.hlsl` 与 `Assets/_Game/Runtime/Unity/TechnicalArt/RealtimePainterly/Production/LivingSkyController.cs`。`QuietStarrySky` 静态贴图路线不是目标。
3. 屋顶中央大片星空是用户明确最喜欢的设计点：保留外围屋顶和梁木框景，显露边缘像颜料被擦开，空间面积足以成为镜头焦点；禁止缩成小天窗或规则洞口。
4. 当前被否决的阶段01场景、其专属网格/材质和两张失败预览已删除，不要恢复或在其上继续修补。旧主场景留在 `Assets/_Game/Content/Scenes/Archive/`；`EditorBuildSettings` 当前没有启用场景。新实施应创建独立美术场景，不受旧玩法流程和灰盒外观约束。
5. 美术目标继续沿用旧画室、暖桌面、窗边蓝色反弹光和窗外亮灯小屋的关系。最终空间应靠有厚度和可信比例的高质量资产、合理构图与灯光成立；不能用粗糙代理几何和额外特效遮盖资产质量问题。

## 目标与判断

目标不是把概念图逐像素复刻进游戏，而是让主流程在实际游戏镜头里读出同一组关系：**有人长期使用的旧画室、桌面暖光、窗边冷蓝反弹，以及窗外有生活气息的夜间村落**。玩家打开屋顶后，星夜沿着原有绘画语言进入室内；外景仍然是一个有远近层次的地方，而不是一张天空贴图。

仓库保留实时绘画后处理、流动星空、树木外景和局部擦开等既有 TA 源码，也保留桌面工作簇、窗框、帘子、画架等旧安装器与独立外景生成代码。它们是可复核的实现素材，不要求新场景沿用旧场景层级、旧镜头或旧玩法流程；导入或复用之前先核对质量、来源和运行效果。旧场景已归档，不应被误认为当前美术目标场景。

主场景资源和 TA 现状见[主场景资源总索引与 TA 表现诊断](../../../ArtLibrary/主场景资源总索引与TA表现诊断.md)。相关代码：[StudioArtSetup.cs](../../../../Assets/_Game/Editor/VisualSprint/StudioArtSetup.cs)、[StudioArtIntegration.cs](../../../../Assets/_Game/Editor/Studio/StudioArtIntegration.cs)、[StudioLandscapePresenter.cs](../../../../Assets/_Game/Runtime/Unity/Presentation/StudioLandscapePresenter.cs)。

## 空间布局

下列方向按新的美术主镜头描述。新场景优先完整呈现空间、资产堆叠和光影关系；旧玩法路线不约束构图。日后如需接回交互，再单独对稳定 ID 和逻辑对象做适配。

| 层次 / 部位 | 规划 | 画面职责 |
|---|---|---|
| 前景 | 保留桌沿、少量画纸或布料作为框景；不让高物件挡住桌面可交互物。 | 给镜头空间感，让玩家先落眼到正在工作的区域。 |
| 中景 | 画架與画布作为第二焦点；窗户作为冷色焦点，两者不要互相重叠。 | 连接“画中的风景”和“窗外现实”。 |
| 背景 | 书架、侧柜、墙上旧画形成少量高低错落的体块；墙面留呼吸空间。 | 说明画室被长期使用，同时压住空墙和空角。 |
| 窗外近景 | 窗两侧少量树冠/树枝，不遮住主要房屋灯点。 | 提供视差和窗洞边缘参照。 |
| 窗外中景 | 三间大小、屋顶和朝向不同的小屋沿坡错开；小路局部可见；每屋只点亮少数窗格。 | 形成可读、安静、有人居住的村落。 |
| 窗外远景 | 两至三层低对比山线和流动星夜；避免远景树木重复成等间距栅栏。 | 支撑纵深，并与室内星夜笔触相接。 |

### 窗外布置原则

- 扩展现有 `StudioArtIntegration.Landscape()` 生成的地形和树木，不把概念图铺成一张远景卡片，也不把房子放在窗玻璃上。
- 房屋作为独立外景子层，沿山坡错开前后与高低。先用有屋顶厚度、墙面明暗和窗洞的简化实体验证轮廓，再决定是否需要下载更细资产。远景建筑可以降低几何细节，但材质与受光不能变成玩具低模。
- 窗户灯光优先用暖色自发光窗格表达。先不为每扇窗新增实时 Point Light；若近景确需光照，仅给一处门灯或最近房屋有限的补光，避免多个小灯互相污染室内色彩。
- 村落根节点应独立于室内建筑的擦除/溶解列表；这样打开屋顶后外景灯火仍有去处。是否让房屋随最终世界状态改变，留到两条结局镜头验证后再决定，不加入新的玩法事实。
- 树、山坡和房屋不得挡住从窗内看出去的主要灯点。采用目标游戏分辨率截图，而不是 Scene 视图近看，判断其读图效果。

## 光照与材质方案

### 灯光层级

| 光源 | 目标行为 | 控制边界 |
|---|---|---|
| 窗外冷主光 | 给窗洞内侧、窗帘轮廓、窗台和相邻墙面提供一致的蓝灰渐变。 | 亮区不能成为纯蓝色描边；室内不能被蓝光整体洗平。 |
| 桌灯暖主光 | 让纸、画笔、陶杯和桌面有一块明确暖色工作区。 | 光照范围由真实灯罩/灯具解释；压住无对应投影的暖色热点。 |
| 室内环境填光 | 保留木梁、书架与墙角的体积，不让阴影死黑。 | 强度低于两盏主光，不新增互相竞争的局部点光。 |
| 村落窗灯 | 在窗外形成稀疏、稳定的生活痕迹。 | 以窗格发光为主，不照亮整片山坡，不闪烁、不抢桌灯。 |
| 星纹/擦开回应 | 作为玩家触发的短暂视觉回应，光落在对应材质表面。 | 不常驻小手电式 Point Light，不用全场粒子代替表面变化。 |

先在固定玩家镜头和固定曝光下只开冷主光与暖主光，检查窗—桌—画架的亮度排序，再加入环境填光。避免通过不断提高 Bloom、后处理强度或粒子量来补救照明结构。

### 表面语言

- **木头：** 增加实际厚边、倒角、木纹方向和接触处磨损；桌沿、梁、窗框保持同一家族但用色深和粗糙度区分新旧。
- **灰泥：** 以低频起伏和宽色块为主，降低墙面高频噪点；转角和窗洞边缘需要真实厚度。
- **亚麻：** 依靠褶皱剪影、织纹和边缘透光表现，不使用大面积均匀半透明塑料感。
- **纸和画布：** 纸张保持暖灰而非纯白；画布看得到绷布侧边、画框关系和颜料厚薄。
- **陶瓷与黄铜：** 只保留少量小而明确的高光，避免道具像塑料或金色镜面。

Painterly 后处理继续作为统一收束层；各材质仍需要自己的粗糙度、法线、颜色层次和尺度正确的笔触。`GameState`、交互 ID、碰撞和规则不参与美术返工。

## 实施分段与验收

### 第 0 段：建立独立美术场景与镜头

保留旧场景归档和现有项目改动；创建独立美术场景，不恢复阶段01失败场景，也不把旧玩法/交互节点当成布局约束。用 Unity Editor API 编辑场景与 Prefab，不手工重写复杂 Unity YAML。先定可复核的主镜头、焦点和空间尺度，再堆叠通过检查的正式资产。

### 第 1 段：窗外灰盒

在窗内玩家镜头中摆出近、中、远三层轮廓和三间房屋，用临时纯色材质检查窗格遮挡、山坡层级与亮灯位置。同步检查屋顶打开后的外景；此段不做细道具、粒子或动态村灯。

**通过条件：** 正常状态下一眼能看出窗外是山谷村落而非排列模型；房屋灯点各自可辨；村落总亮度仍明显低于桌面主灯。

### 第 2 段：室内结构与剪影

先改窗框深度和帘褶，再核桌子、画架、书架与背景墙的比例和遮挡关系。优先复用现有视觉资产和安装器代码；若正式场景里实体层级不同，按当前场景结构调整工具，不直接覆盖玩法根节点。

**通过条件：** 小分辨率截图仍能清楚区分桌面工作簇、画架和窗；关闭特效时室内依然由真实资产和材质结构成立，而不是灰盒。

### 第 3 段：材质和两盏主光

按木、灰泥、亚麻、纸、陶瓷逐类校色；固定相机曝光，建立窗外冷光与桌灯暖光，再补少量室内填光。分别查看标准路线和蓝光状态，避免某个结局才好看。

**通过条件：** 蓝光确实落在窗框、窗台、帘褶与邻墙；暖灯能解释桌面亮区；无大块无来源热点和压死的黑影。

### 第 4 段：接回 TA / VFX

让局部擦开贴着屋顶/墙面几何和触发位置走；让星夜流动的笔触尺度延伸到窗边和室内受光面。粒子仅用于窗边真实光区与短时触发点。灯罩星纹优先用投影/贴花或随灯光方向变化的表面图案验证，不先堆 VFX 包。

**通过条件：** 玩家能从触发点看懂变化发生在哪里、沿什么表面发展、最终留下了什么；效果在常规视距和实际游戏分辨率下清晰可见。

### 第 5 段：镜头与运行检查

在独立美术场景里检查常态室内、窗外村落、屋顶显露和星空流动；检查 Console、构图遮挡、曝光与材质响应。这个交接阶段不要求恢复旧主流程、旧测试或旧构建入口；接回玩法属于后续单独任务。

## 明确不做的事

- 不把任一概念图直接放进 `Assets/` 充当天空、墙面或画布贴图；这些图片是 AI 生成的美术方向参考。
- 不把旧场景的交互点、碰撞、谜题事实或路线当作新美术场景的空间约束；玩法接回前也不要顺手改这些逻辑。
- 不把远景村落做成可探索的新区域，也不让窗灯暗示未实现的交互。
- 不在灰盒构图和两主光通过前购买、导入一批新模型或追加大型粒子包。
- 屋顶显露以概念图中“中央大片区域成为星空”为目标比例；推进范围按新场景镜头构图确定，并保留清楚的梁木框景。

## 本轮生成提示词组

五张图片均用内置 ImageGen 生成，并以现有概念图作风格参考。提示词共同要求：旧画室、手绘半写实 3D 环境、暖桌灯与冷蓝窗光、木/灰泥/亚麻/纸/陶瓷材质统一、可读空间层次、无文字和 UI。分图分别补充：

1. **总览镜头：** 前景厚木桌与有序工具簇，中景画架，背景深窗洞和书架；窗外可见三至四间错落、少数窗户亮暖光的小屋、山坡、小路、远山和靛蓝星夜。
2. **村落视图：** 从窗内望向山谷；树枝作近景框景，坡地与错落房屋作中景，云、山线和星夜作远景；灯火稀疏且不排成一线。
3. **窗边光照：** 近看深窗洞、厚木框、窗台、亚麻帘与墙面；冷蓝光连续衰减，桌灯暖光只触及下部，避免霓虹描边和满屋体积雾。
4. **屋顶显露：** 从室内仰视梁和灰泥天花板，星夜沿局部不规则笔刷边界显露；保持建筑表面连续，避免圆形传送门和矩形洞口。
5. **桌面工作簇：** 中景展示厚桌沿、画架、画布侧边、水杯、画笔、调色与少量纸张；暖光集中桌面，冷光只描出窗侧边缘。
