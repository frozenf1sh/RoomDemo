# 绘画效果接入

生产组件独立于游戏规则。它们只处理画面和时间，不读写 `GameState`。

## 接入步骤

1. 选中主摄像机使用的 `Universal Renderer Data`，在菜单“游戏 → 技术美术 → 生产接入”中安装绘画 Renderer Feature。保留现有 Feature，不替换项目全局 Pipeline。
2. 给主摄像机安装 `PainterlyCamera` 控制组件。Overlay Canvas 继续在效果之后绘制；World Space UI 使用独立 Overlay Camera。
3. 从 `Assets/_Game/Content/TechnicalArt/Production/Prefabs/` 拖入需要的 Prefab，并按下表绑定摄像机或目标 Renderer。

| 组件 | 用途 | 常用入口 |
|---|---|---|
| `PainterlyStyleController` | 同一绘画算法的全局强度档位 | `TransitionTo(stage, seconds)`、`SetPainterlyIntensity(0–1)`；主场景保持统一画风 |
| `PainterlyLocalController` | 指定 Renderer 或世界区域的局部绘画化 | `SetTargets(...)`、`TransitionTo(...)`、`Clear()` |
| `LivingSkyController` | 天空显露与原版颜料、笔势运动 | `RevealTo(coverage, seconds)`、`FlowTo(flow, seconds)` |
| `LivingWaterController` | 杯水、颜料和湿痕 | `SetState(...)`、`SetFlow(...)`、`ResetEffect()` |
| `PainterlyRewriteController` | 沿笔势显露后方几何 | `RewriteTo(amount, seconds)`、`SetRewrite(...)` |

场景和 Prefab 的生成入口在 `Assets/_Game/Editor/TechnicalArt/RealtimePainterly/Production/ProductionResourceBuilder.cs`。在 Unity Editor 中运行对应菜单项；生成器会拒绝覆盖未保存场景。移动或新增资源时保留 `.meta`。

效果复位时清除各自的运行时历史。暂停或手动播放序列时，先关闭自动时间，再由序列推进；场景重开时恢复 Reality、清除局部影响并取消旧演出。

当前画室采用**固定画幅**：主摄像机上的 `FixedViewSky` 用原 Hero 的绘画参数（Painterly 0.90、ACES、Bloom）实时生成画面，`FixedViewSkyFeature` 在房间真实深度后合成。画室没有天空球网格；镜头姿态、正式构建入口与玩法事实不变。UI 在合成之后绘制。源摄像机独占第 31 层，场景物体请保留在原有层。

`FlowTo` 再次控制实际 GPU 颜料平流与动态笔势，`LightTo` 单独控制暖星；`Paused` 冻结两份历史。默认 `HistorySeconds=21`、`HistoryBlendSeconds=6`：首 15 秒沿用原 Hero 的连续演变，之后两份实时历史平滑交接，避免同一画面无限累积拉伸；没有导入画作或预烘焙动画。`BoundedHistory=false` 仅供原算法对照，不建议长时间正式运行。

新会话由 `AtelierFinalePresenter.Bind` 调用 `ResetEffect()`，取消旧历史；固定画幅同时重置自己的 TAA。固定视角下 `SkyYawDegrees`、`SkyElevationDegrees`、`PanoramaRepeats` 以及旧材质的球面投影参数不参与主画面。调整主效果请使用 Flow、Light、Coverage 和上述历史参数，勿再用微光替代整片颜料运动。

独立复刻场景：`Assets/_Game/Content/Scenes/Experiments/TechnicalArt/FixedViewSkyBenchmark.unity`。增量安装菜单：`游戏 → 技术美术 → 固定画幅星夜`；不会重建房间，未保存场景会阻止安装。视觉与运行边界见[固定画幅星夜复刻](固定画幅星夜复刻.md)。取证文件只放本地忽略目录，弃用的微光方案不保留在交付资源中。
