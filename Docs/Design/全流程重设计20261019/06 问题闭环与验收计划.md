# 新流程问题闭环与验收计划

本表的“设计已闭合”只表示已有明确方案、条件和恢复路径，不表示代码已实现或玩家已验证。新主线验收须等后续实施；本轮实际做过的工程验证单列在模块化记录中。

## 一 体验反馈逐项关闭到设计

| 问题 | 设计解法与步骤 | 要取得的验收证据 |
| --- | --- | --- |
| 抽象词无法指向现实目标 | P02至P04先做实物接触；配方只生成画法；刮刀迁移先学两种接触方式 | 首次玩家能指出下一目标，主持人不解释配方用在哪 |
| 洗笔后重复点水领奖 | P03有效接触同次记录可见结果观察 | 事件批次、杯水画面和新材料提示同时有据，离开再回不重复 |
| 点灯刮板同类重复领取 | P15和P18动作结果自动记录 | 不再点灯芯或木纹也能继续主线 |
| 灵感存在但玩家不知道 | P05新灵感专名提醒和未读笔记，区分观察/灵感/已合成画法 | 玩家能说出自己现在是“有线索”还是“已有画笔” |
| 现实变化太轻微 | K2接触局部形态变化，0.2秒内开始明显结果 | 主镜头和近景各一组前后对照及运行观察 |
| 默认保留所有旧交互 | 旧拉帘退出必要线，旧抽象词作用实物改为直接操作；旧能力按用途复用 | 新流程没有隐藏的旧日序或三次解释门槛 |

## 三 后续实施的领域和应用测试

仅在相关逻辑开始实施后运行这些针对性测试，不以旧主线全套替代新线。

| 用例 | 输入 | 应有结果 |
| --- | --- | --- |
| D01 非顺序观察 | 先蜡笔、再洗笔、再杯 | 所需材料齐备后同样发现灵感，不代授未点物体 |
| D02 同次动作观察 | 有效洗笔命令 | Washed与蓝色流动观察同批出现，无延时领奖 |
| D03 幂等接触 | 同一动作序号重复提交 | 不刷观察、灵感、计数或提示 |
| D04 物体来源校验 | 配方试图产出屋顶/房间 | 内容校验拒绝 |
| D05 非法配方 | 两项不匹配或试图放第三项 | 失败不消费；第三项拒绝加入，不悄悄替换前两项 |
| D06 阶段推进 | 未合笔刷、2笔或工具没学就收层 | 拒绝并返回具体缺项 |
| D07 三笔提前结束 | 合法三笔后收层 | 当前层封存，余量放弃，总账守恒 |
| D08 完整预算 | 极小极大交替、全最小、全最大、默认 | 五/六笔均耗尽，末笔仍合法，余量非负 |
| D09 撤销 | 提交后撤销最后笔 | 原量退回，笔数和合法范围恢复，旧层不变 |
| D10 最后一笔重复提交 | 相同StrokeId重放 | 仅一笔、仅扣一次 |
| D11 早期屋顶输入 | 异常前或未调查直接刮 | 拒绝，不获屋顶物体 |
| D12 首次屋面小试 | 有效第一刮后回画布 | 仍可普通定稿 |
| D13 第二次揭底 | 已小试后再沿边刮 | 隐藏路线锁定，普通定稿不可用 |
| D14 终局竞争 | 同帧先后提交两种终局 | 首个合法命令接受，第二个拒绝 |
| D15 全房门槛 | 只开屋顶未亲点房间就刮墙 | 不自动擦全屋 |
| D16 恢复 | 从第四阶段再试 | 三层画保留，最终事实、输入和演出清空 |
| D17 收色后改画 | 最终涂抹后再落笔或撤销 | 收色版本失效且实际画面恢复；再次刀面接触后才可定稿 |
| D18 第四层撤销到两笔 | 曾开放刮刀后撤销 | 普通定稿和两次屋面揭底都重新拒绝，不因按钮曾开放而漏检 |

## 四 场景 TA UI 和声音检查

运行检查包括接触前后、近景与主镜头、暂停中断、N和Esc顺序、失焦时松开、旧材质恢复、天空源镜头层、透明物深度、金丝与底稿组合、五次重开资源稳定。纯场景/美术修改不逐项执行领域全套。

真实构建UI检查至少覆盖1024×640、1280×800、1920×1080及超宽窗口。长材料名、双词摆放及第三项拒绝、灵感提示、颜料耗尽、最后一笔固定大小、第三阶段缺工具、两个结局都要实际显示。自动文字扫描无法证明中文字形与小窗口布局合格。

声音可听验收单独记录：洗笔首接触、砂纸划火与灯芯接火是否分得开，刮干色与推软色是否有区别，旁白有没有盖住结果，静音是否仍能完成。没有实际听过就标待听，不写“听感通过”。

## 五 首次玩家评审记录模板

每位参与者记录日期、构建版本、是否读过文档、使用分辨率、输入辅助模式。按P步骤记首次看向何处、说出的意图、首个尝试、停顿秒数、错误理解和主持人是否介入。计时只用于研究，不进入游戏规则。

建议提问：“刚才发生了什么？”“你现在想做什么？”“你为什么觉得这个物品能用？”避免直接问“你是不是该点屋顶”。普通路线结束后问玩家是否认为自己的作品成立；隐藏路线只记录玩家自然发现到哪一步，不提前告诉答案。

问题严重度：阻塞为不能继续或只能靠主持人；高为误学规则、误入不可逆分支、看不见成功；中为反复往返或提示噪声；低为不影响理解的润色。出现阻塞或高问题必须回设计步骤修正，不能以测试已经跑通关闭。

## 六 本轮和后续实施的边界

本轮交付是完整设计、概念参考、UI交接和现有场景Prefab拆分。新规则、新画布账本、阶段底稿、镜像、刮刀和结尾调整都需要后续代码与内容实施。自动化可证明命令与引用一致，运行截图可证明画面在某次执行中存在；真人理解、音效听感和游玩时长只按实际试玩证据记录。
