## 一 是否与UI的工作重叠

画布核心已经实现；正式界面仍由UI同学负责。共有的是同一组接口，需要替换的是临时按钮和输入，不是把同一套系统再做一次。

| 冻鱼与Codex已经提供 | UI同学现在负责 |
| --- | --- |
| 四层账本、整数颜料、末笔合法范围、三笔完成、撤销退款、世代/版本/重发保护 | 大小/旋转控件、颜料和笔数展示、撤销/完成/返回按钮、禁用原因与工具位 |
| 真实作品RT、原PNG叠放、实际画布UV、Alpha画外许可、撤销重建 | Workspace布局、指针捕获、同参数预览、用已有纹理显示作品 |
| 物件亲点来源、配方、已知笔刷ID与原始图样 | **笔记本笔刷条目、形成结果页、预览、来源和旧笔刷回看**；我们保留文字占位 |
| 去重发现事件、开场输入许可和会话生命周期 | **笔记入口上方新词条提示、未读、首次开书导读**；不把这些阅读状态加入领域 |
| N01/N02/N03原稿采用文本与触发、完整组播放完成通知 | 左上字幕视图、字号/两行排版与后续回读；不同时启动第二个台词播放器 |

实际控件、提示和导读需求见[04](<04 UI开发交接与画布工作.md>)第零、十二至十四节。分工、分支和PR顺序见[10](<10 分工排期与联调协议.md>)。UI同学不改主场景、Domain、GameSession、AtelierFlowCanvas或全局输入；需要的附加接口由我们增量补齐。

## 二 共同基线和并行方式

本次开始时，远端`codex/atelier-four-stage-ui`没有独有提交，仍在旧文档基线`250eeb5`。将其正常快进到包含本次修订的场景分支最新提交；以后UI在`codex/atelier-four-stage-ui`，我们在`codex/atelier-scene-flow`分别开发。不会强推或删除UI提交。

新人用`git fetch origin`后跟踪UI分支，已有分支且没有自己新提交时`git pull --ff-only`，再`git lfs pull`。若已在本地开发，先保存自己的改动，再普通合并更新；不强制重置。首批UI可向场景分支提联调PR，由我们装配Prefab和真实引用，再统一交main。不要复制一份修改后的AtelierPlayable互相覆盖。

UI可以立即用已知首层接口开发Workspace、笔刷页、提示和导读。我们继续第二阶段镜面、刮刀及后续流程，不开发正式笔记笔刷页。UI的Fake预览放在约定独立预览场景，按真实字段造数据，不能把Fake的笔刷或画作灌进正式GameState。

## 三 本轮实际开场

进入AtelierPlayable就开始N01。第一帧世界为黑色并已建立第一阶段底稿；约2.4秒退黑，约4.8秒结束失焦，之后常态使用稳定草稿。旁白在Overlay左上按完整句显示，整组播放完之前，世界点击、N/Tab、Esc、空格、返回和笔记入口均不接受操作。开场无跳过控件。旁白结束只恢复输入，不替玩家读取便签或收集物品。

第一阶段保留杯水、洗笔画笔、便签、实际画布和窗台涂鸦的实色，其余外围进入草稿。右侧工作灯、桌布和散落颜料、右书柜、天花板均遮挡。清晰区使用这些Renderer实际世界边界，画笔运动和近景移动不会变成静态截图遮罩。第一层主动完成后解除新增外围与左侧遮挡，窗景主体继续保留底稿。

开场结束后可以直接观察杯、笔或涂鸦，不强制先读便签。先前的便签前置已从新规则表移除；实际洗笔仍要求分别亲点杯与画笔，接触才产生蓝色和流动。N01结束不是新的世界事实，也不会自动授予完整概念。

## 五 UI同学现在能绑定什么

在场景装配注入`AtelierFlowGameplay`，不要在UI Prefab的Awake里Find中文物件名。等Start完成后绑定`Session`与`CanvasPort`，具体画布字段和世代/版本命令示例见12第三节。

- `IsOpening`与`GameplayInputEnabled`：UI读取开场许可。开场禁止可点的透明按钮、笔记通知和导读；不要用自己的固定秒数推测结束。正式字幕暂继续绑`AtelierFlowNarration.Label/Opacity`，N01完成事件由现有播放生命周期发出，后续配音接入同一完成条件。
- `SetExternalCanvasWorkspaceActive(true)`：正式Workspace接管画布手势和按钮；旧的默认盖章、临时完成/返回控件停止参与。解绑时传false恢复功能占位。该开关不修改作品、预算或世界事实。只让一个控制器提交一枚笔触。
- `NotebookBackHandler`：UI注册`Func<bool>`，先收起导读/详情并返回true消费Esc；没有内部浮层时返回false，由全局输入关书。生命周期退出时解除同一注册。
- `Session.EventRaised`：已有`ClueDiscovered`、`CombinationSucceeded`和`AtelierCanvasChanged`。新词通知用去重发现，笔刷页用真实配方与KnownClues，完成/撤销用真实作品变化。UI不能凭动画结束自己授予结果。
- `CanvasPort.Brushes`：1至4对应原始PNG，用于笔记笔刷图样预览。`CanvasPort.CanvasTexture`才是玩家实际作品。两类纹理均由外部提供，UI不重复导入或销毁。

`GameplayInputEnabled`是开场/取消帧许可，正式控件还要结合`IsPaused`、`Notebook.IsOpen`和`IsCanvasFocused`；不能把true当成完整的落笔许可。当前字幕、便签正文和临时调查框有场景实例覆盖，正式UI合入时由我们清理占位覆盖/更换References，UI同学只维护母版和预览。

前三条是本轮新增的并行接入口。Workspace使用独立References组件交付；主场景最终接线仍由我们保存。新词条提示和首次导读目前只补进交接，不宣称正式UI已经实现。

## 六 检查与本机演示

`AtelierOpeningFlowTests`12/12通过，含不读可选便签直接形成首笔刷、便签不代授来源等用例；不跑归档旧全量测试。保存重开后新便签与七个清晰范围引用保留，最终编译无错误。实际构建Succeeded，0错误、4项既有警告（开发Pipeline Runtime配置、碰撞预烘焙、两个未使用Core Debug Shader剥离）。1280×720和1024×640的实际Player自动回放均0错误，已查看两种窗口下的新便签字形和完整显示。
