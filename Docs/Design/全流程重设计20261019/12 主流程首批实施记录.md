# 主流程首批实施记录

2026年10月19日，开发分支`codex/atelier-scene-flow`。本批实施10号文档的A批场景侧：P00至P07，以及收完第一层后的P08左侧显色。独立TA基线已经提交推送为`8eef425`，五项视觉方向由冻鱼确认通过；手镜滑块、程序入口与演示均限制在±15度。

本批开发入口是`Assets/_Game/Content/Scenes/AtelierPlayable.unity`。正式AtelierNight、正式构建列表与现有星空维持原状。新流程停用旧静物规则和输入，旧类与Prefab继续留作历史实现和引用来源。二至四阶段玩法及双结局还没有接上；当前不是完整四阶段试玩包。

## 一 现在如何操作

1. 进入AtelierPlayable，点桌沿便条。沿用场景现有便条，原稿没有提供正式便签全文。阅读不限时，右键、返回按钮或Esc合上后进入轻重影与局部底稿。空格可跳过这段视觉；不自动领取其他实物。
2. 点杯水靠近，记录“透明”“映射”；亲点杯沿洗笔画笔，再点杯水发起洗笔。也可以先点笔，再点水。笔尖实际浸入水面时才提交洗笔，蓝色与流动当场开始，同一命令记录结果；无需再点一次领结果。返回、暂停、失焦在接触前会取消请求。
3. 返回画室，点窗台小画，记录“奔放”“杂乱”。当前正面仍是彩色线条位置占位，最终蜡笔画待策划/美术补齐。
4. N打开现有笔记本，每次只摆两项并提交：透明＋蓝色→冰蓝；流动＋奔放→卷涡；冰蓝＋卷涡→卷涡笔刷。组合不会替玩家落笔，三次配方也不会触发旧的自动锁画布。
5. 关笔记，点画架进入固定近景。鼠标预览原始1.png，每次左键按下至松开只确认一枚，允许自由位置、重叠。拖过UI、移出画布、失焦或返回取消未确认笔印。画外只剩不足35%有效Alpha的误落会拒绝，不按构图、覆盖率或美观评分。
6. 默认第一层六笔恰好用尽100单位；两笔不能完成，第三笔起“完成绘画”可用。提前收层会明确记下放弃余量，不结转下一层；耗尽颜料仍需玩家主动完成。返回再进保留作品。
7. 第一层完成后，左侧石膏/手镜组恢复实色，窗景局部仍保留底稿，播放原稿N03。本批可玩范围到此；第二阶段物件调查与笔刷尚待B批，不要按旧静物攻略继续。

当前默认大小、角度为场景侧功能输入。大小/旋转滑块、撤销按钮、颜料条、工具位、原稿左上旁白与物件左侧两行排版由UI同学的Workspace提交接入。本批没有修改其NotebookView、NotebookCanvasView或UI母版。底层已经支持合法成本、任意整度旋转和撤销，不能把底层能力写成正式控件已经交付。

## 二 实际装配与规则边界

| 部分 | 现在的职责 |
| --- | --- |
| `Domain/AtelierFlow/AtelierFlowRules.cs` | 独立首批内容表，观察来源、洗笔条件、三条有限配方；二至四笔刷仅保留身份，没有调试赠送 |
| `GameState.AtelierCanvas` | 唯一作品账本，四层计划6/5/5/6笔，每层100量，当前合法成本12至24及动态收窄；不可变笔触和只读列表 |
| `GameSession.AtelierCanvas.cs` | 世代、版本、笔触ID去重；提交、撤销、收层原子完成后再发布事件 |

| `AtelierFlowCanvas` | 唯一1024平方作品RT、原始PNG叠放、裁边/面积标定、临时预览、Alpha画外许可、按领域笔触重建 |
| `AtelierFlowWash` | 接触前的请求与取消、真实笔尖高度核对、有效接触命令、散色材质生命周期 |
| `AtelierFlowNarration` | 09号文档采用的N01/N02/N03原文，完整句分页、去重与暂停；新进度在句末替换过时引导，播放不授予事实或阻挡输入 |
| `AtelierDraftCamera`与`AtelierDraftFeature` | 纯视觉参数和世界锚定局部底稿；接收已成立阶段，在原Renderer追加通道，不替换原管线 |

代码路径以`Assets/_Game/Runtime/`为根。新视觉位于`Content/ArtRebuild/FourStage/`，四张原始图样位于`Content/ArtRebuild/Brushes/FourStage/`。新物件视觉是独立Prefab`PF_首批新增物件视觉`，源自已验收TA副本；没有把实验滑块/HUD装进主场景。小画Collider与固定近景由主场景装配，Logic/Visual仍分离。

本批把动作的“附加亲点来源”和“当场观察结果”写入有限SceneAction规则。规则校验只允许动作产生Observation，禁止物体和完整概念；旧动作参数默认空，旧来源规则仍有效。洗笔要求已亲点杯和笔，便条不代授。所有结果先完整写入，再通知UI、作品和TA读取同一状态。

颜料算法：下一笔下限为`max(12, R-(n-1)*24)`，上限为`min(24, R-(n-1)*12)`，R为余额，n为含本笔的剩余计划笔数。默认用量取`ceil(R/n)`并夹入合法区间。最后一笔上下限自动相等，仍在12至24内。前三笔可重叠，不检查“画够了多少面积”。撤销只删当前未封存层的最后一笔，退还该笔原始成本，旧层不可撤销。

## 三 给UI同学的真实接入入口

先读[10 分工与联调](<10 分工排期与联调协议.md>)和[04 UI交接](<04 UI开发交接与画布工作.md>)。本批接口已经存在，UI展示合同/Fake可以继续保留，但正式接入不再建立另一份作品或颜料账本。

从场景装配提供`AtelierFlowGameplay`及其`Session`、`CanvasPort`，等首批Start绑定完成再订阅。读`Session.SessionEpoch`、`CanvasPort.Document.Revision`、`Document.Current`；该层含`Id/Count/PlannedStrokes/RemainingPaint/MinCost/MaxCost/Sealed`。读`CanvasPort.CanvasTexture`显示同一作品，UI不得Release/Destroy它。原始笔刷用`CanvasPort.Brushes[layer.Id-1]`，共用已导入PNG和meta，不再重复导入改变GUID。

预览调用`CanvasPort.Preview(uv, visible, selectedCost, selectedAngle)`，取消时visible=false；预览不改作品。大小步用整数成本，实际可见尺寸由同一份有效Alpha裁边标定；不要按带透明空边的整张PNG面积再算一遍。

正式落笔必须保留按下时的世代、版本、ID、选中成本与角度，在松开时复查。同步入口`CanvasPort.Commit(uv,cost,angle,id)`读取当前世代/版本，适合已经由场景侧检查过捕获快照的即时请求；UI异步请求应使用：

```csharp
// 此处uv已经由世界表面射线得到，不能拿UI矩形坐标直接冒充。
if (!canvas.IsPlacementValid(uv, selectedCost, selectedAngle))
    return;
var stroke = new AtelierStroke(strokeId, layerId,
    Mathf.RoundToInt(uv.x * 10000), Mathf.RoundToInt(uv.y * 10000),
    selectedAngle, selectedCost);
var result = session.CommitAtelierStroke(epochAtPress, revisionAtPress, stroke);
```

撤销用`session.UndoAtelierStroke(epoch,revision)`，收层用`session.FinishAtelierLayer(epoch,revision)`。即时世界控件也可调用`CanvasPort.Undo()/Finish()`。结果的`Accepted/AlreadyApplied/Reason/Events`由真实用例返回；拒绝不扣量，相同ID且相同内容重发不重复扣量。撤销、提交、收层使版本递增并取消旧预览。监听`Session.EventRaised`中的`AtelierCanvasChanged`刷新快照；订阅者只读，不在回调里递归提交命令。所有订阅在OnDisable/销毁时对称解除。

第一层`CanUndo = !layer.Sealed && layer.Count > 0`，`CanFinish = layer.Count >= 3 && !layer.Sealed`，还须结合暂停/笔记/镜头输入许可。三、四层额外动作门槛已在领域命令预留，真实动作尚未实现；当前不要展示已经可用的最终刮刀或普通结局。后续B/C会一起补明确快照，禁止UI绕过Finish结果自行推进阶段。
