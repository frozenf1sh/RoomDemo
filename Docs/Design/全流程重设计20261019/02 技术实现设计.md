## 一 当前工程与替换范围

实查环境为 Unity 6000.6.3f1、URP 17.6.0、Input System 1.20.0。开发入口仍是 AtelierPlayable，正式构建列表保留 AtelierNight。主要现有入口如下。

| 现有文件或系统 | 可复用部分 | 新线需要改变的部分 |
| --- | --- | --- |
| AtelierGameplay | 固定镜头、射线拾取、近景返回、暂停和会话装配 | 旧的四项静物和三次画内解释入口改接阶段数据；不继续扩大单一脚本 |
| AtelierRules RuleEngine GameState | 观察、有限配方、动作条件、反应闭包、去重 | 新建阶段内容规则表；必要时扩展明确的画布命令，不能改成Unity判断配方 |
| GameSession | 统一命令入口、事件发布、只读查询 | 新增画笔提交、撤销与收层用例；现有PerformAction不能携带所有笔触数据 |
| NotebookView NotebookCanvasView | 左页统一可用材料、最多两词、点放或拖放、提交才判定 | 来源回看、笔刷结果预览、新灵感通知和用户主动提示 |
| AtelierPaintingPresenter | 画布近景与局部材质展示 | 当前有限静物显露不是原稿图示的自由放置笔刷画布；需要新的印章命令渲染器 |

| AtelierFinalePresenter LivingSkyController FixedViewSky | 统一世界擦除、程序化颜料平流、真实深度后合成 | 增加局部试刮和继续刮开阶段；保留亲点天空和房间；不导入概念图天空 |
| NarrationSystem AtelierNarration | 独立旁白节点、文本和时序配置 | ReplaceAll式抢占需改为内容优先级，低优先级不能盖掉必要反馈 |

## 二 事实和表现的数据归属

领域层持有已知物件、观察、已完成配方、阶段、已提交画笔及颜料账本、工具学习、屋面试刮和终局。应用层负责检查命令、按顺序发布事件、处理撤销和练习快照。Unity层持有鼠标预览、临时选词、镜头缓动、材质插值、音源、RT和输入捕获。

笔触大小属于玩家的明确创作输入，会影响有限颜料和画面重建，因此其离散大小与颜料消费应进入专用画布数据；Painterly强度、天空速度、底稿显色进度仍只属于表现，不得混进GameState。画布数据是本游戏的有限文档，不建立通用画图框架、自由节点图或磁盘存档系统。

拟议稳定ID采用atelier.flow.*前缀；既有ObjectId不为翻译更名。阶段标签、对象中文名和ID分开配置。物件定义应记录来源、调查细节、可用阶段、主镜头可见位置、近景机位和Logic/Visual引用，避免运行时按中文名Find。

阶段不用真实时钟推进。完成收层是明确命令；颜料用完只让画布停止接收新落笔，不自动替玩家点“完成绘画”。终局命令要在同一入口执行互斥检查，不能让两个Presenter各自判断并开播。

## 四 动作观察随同一次命令产生

解决洗笔后重复点击的正确位置是规则内容，不是Presenter延迟回调。将洗笔拆为预览接触和有效接触：鼠标输入控制笔尖接近；有效接触时提交wash_release_pigment。规则检查来源物件已被亲点、阶段可操作、未提交，再同次产生Washed、blue、flowing_observation以及后续灵感发现。Unity在同一接触帧开启颜料渲染；不等整个摇笔动画结束才加观察。

点灯同理以火柴与灯芯有效接触作为命令提交点。刮板以合法表面累计有效接触达到短阈值作为动作证据。阈值只确认玩家做过动作，不承担“观察是否看懂”的判定。提交前取消没有事实；提交后离开近景，表现直接恢复到事实对应的结果，不重复授予。

灵感依赖观察，不能产出物体。UI收到本次命令的事件批次，合并为一个结果提示和一个新灵感提醒，避免同一帧排出六条Toast。重复提交返回AlreadyApplied或当前状态说明，不再次播整段发现音。

## 五 画布用例和颜料账本

详细数值与交互合同见UI交接。领域侧拟议CanvasLayerState包含LayerId、BrushId、BudgetUnits、PlannedStrokeCount、CommittedStroke列表。Stroke至少有StrokeId、CenterU、CenterV、AngleStep、SizeStep、PaintUnits、Seed。UV和角度离散化后传入，规则不依赖UnityEngine.Vector2；实际渲染坐标由Unity适配器转换。

四层计划笔数依次为6、5、5、6，总颜料各100单位，每笔12至24单位。实际合法区间根据剩余预算和剩余计划笔数收紧。第三笔以后允许提前收层，余量记为DiscardedUnits且不可转移。收层结果必须满足CommittedUnits＋DiscardedUnits＝100，完整耗尽时DiscardedUnits为0。画布放置完全自由，不用覆盖率、分区、距离或美观分数判完成。

CommitStroke命令只在当前层、笔刷已形成、输入合法、仍有颜料时接受；扣量与加一条笔触不可分开。UndoLastStroke只撤当前未收层的最后一笔，精确退还该笔原量；不会用当前滑块大小重新计算。FinishLayer检查至少3笔和其他阶段门槛，再一次性封存层和余量。UI禁止按钮不是唯一防线，命令入口仍须复核。

不采用逐帧把鼠标路径持续盖章的方式，否则大范围拖动可用一笔颜料无限铺图。每次按下到松开只产生一枚可缩放、旋转的策划笔刷图样，拖动调整落点。未来若需要真正连续的轨迹画法，必须另行定义按弧长和面积付费；不在本次合同里暗中加入。

## 六 画布渲染与内存所有权

推荐以笔触命令列表作为重建来源，当前作品使用分层RenderTexture。用户提供的四张PNG是合法的候选画布笔刷素材，不是整张结果图。导入保留Alpha，启用sRGB颜色，禁止黑底补色，压缩质量通过深蓝底和米白底对照检查；实际黑边、色边和UV留白需要单独查验。

首轮每层1024平方、RGBA8。四层约16 MiB，合成图4 MiB，当前预览和回放乒乓缓冲各4 MiB，基础预算约28 MiB，不含底图和笔刷采样。质量档可降为512，近景确需2048时再测目标机，不默认四层全上4K。GPU资源每次关闭画布不释放作品，但会话重开、场景退出和编辑预览结束必须统一释放。

每次提交按笔触顺序合成，预览单独绘制，不写入作品。撤销清当前层RT并按剩余命令重放，最多六笔，成本明确，不用每笔保存整张图。阶段顺序就是叠层顺序，不为得到标准星夜偷偷更改玩家遮挡关系。随机纹理抖动用笔触Seed固定，撤销和重建不应改变上一笔外观。

RT重建后画布材质从同一拥有者获取句柄；UI只拿预览Texture引用，不负责释放世界画布RT。正式构建检查线性空间、透明混合、Mip与色调映射，确保笔记预览和世界画布颜色有可解释的一致关系。

最终刀面收色保存有限的接触路径与CanvasRevision。只有收色版本等于当前画布版本且第四层仍至少三笔，才能普通定稿。新增或撤销笔触会递增版本，先恢复命令列表对应画面并清掉过期收色，再重新提示一次刀面接触；离开近景与打开笔记不改变版本。每次屋面揭底也在接受命令时复查笔数，不能依赖此前开放过工具按钮。

## 七 输入路由和工具接触

开场N01未结束时优先关闭全部游戏输入和笔记入口，不接受N/Tab、Esc或空格跳过；完成仅交回输入，不添加领域事实。之后单一输入协调器按“结束菜单→暂停→笔记导读/详情→笔记/阅读浮层→画布UI→当前检视工具→世界拾取”的优先序消费事件。每次指针按下只归一个消费者；拖动期间捕获指针，失焦、Esc、窗口外松开、对象销毁均触发Cancel。UI Button点击不能穿透成画布一笔，合笔记那一帧不能继续触发世界物件。

画布输入只认实际画布局部UV，使用相同屏幕映射绘制预览和提交。透视近景的UV应来自画布碰撞或平面交点，不拿整屏坐标直接贴图。有效笔印中心在画布内、Alpha可见面积达到约35%是边缘误触防护，不是构图评分；预览在提交前清楚标示可用与不可用。叠放同处是允许的创作行为，每次真实提交都照常扣量。

刮刀接触采用来源表面ID、工具模式、局部接触路径和一次动作序号。刀面推色只作用于颜料板软色与画布；刀刃揭底作用于板上干色、已亲点屋面以及后期已调查墙面。Collider许可、可见材质表面和逻辑拾取共用同一可用状态，已刮开区域不得继续挡住后方天空。

## 八 底稿与隐藏异常的事实消费

阶段适配器读取收层事实后先播放对应完整旁白，完成回调才让显色控制器逐步开放该阶段的显式Renderer清单；背景始终保留底稿，已开放物件累积保留。物体是否可调查由规则决定，底稿浓度不反向影响规则。近景切换只更换投影与局部遮罩，不能重新计算“玩家现在是否完成阶段”。

异常有独立的已成立事实、首次展示提醒和持久细痕表现。已成立事实可在灯近景发生；展示提醒等待回主视角再播一次。持久细痕由事实恢复，重进近景或暂停不清除。不会用“几秒后关闭Collider”造成一次性隐藏入口。

屋面局部刮开场先保留大部分灰泥与木梁，擦除材质需同步DepthOnly、DepthNormals、ShadowCaster和可见Forward裁剪。天空在真实深度后合成，不能把一张天空图贴到屋顶正面。进入全房间擦除前，领域仍要求天空、跨材质笔迹和房间的实际点击。Presenter仅播放既定擦开方向，不替玩家生成物件或新观察。

## 九 场景和Prefab边界

场景保留会话装配器、艺术根、跨模块引用与机位；工作簇拆为可复用Prefab。优先自然边界：建筑中的地板、窗组件、屋顶各块；家具各件；洗笔、点灯、拉帘、湿色工作簇；UI的笔记、藏品、暂停、便条、调查、字幕与提醒。避免把1888个展开节点每个做成一个无意义Prefab。

跨场景对象引用不能直接写入Prefab资产。第一轮迁移保留现有场景引用覆盖，并生成外部引用清单；第二轮接新主线时改为场景组合根显式注入模块引用。不能为了“自包含”把所有系统塞回一个巨大Prefab。已有Prefab保留原GUID，不能覆盖手调UI母版。

迁移工具要求当前无未保存场景、不在Play、不存在同名新资源，保存前比较物件数量、层级顺序、Transform、组件数据、稳定ID与引用关系；保存后重新打开再比较，失败回到场景原文件并保留诊断。详细本轮结果以实际报告为准。

## 十 生命周期与回看快照

新会话先取消所有旧CancellationToken或协程、停止音源、清除指针捕获、释放RT及材质克隆、复位Shader全局值，再创建会话并绑定。订阅采用Bind先解绑、OnDisable或OnDestroy清理；Presenter不互相调用。

“从第四阶段再试”只保留内存中阶段四入口快照，包含前三层笔触列表和规则允许的既知材料。恢复通过应用层显式构造会话和画布数据，不由UI直接拷贝GameState集合。快照不包含屋面和房间调查、最终点灯结果或已提交终局。未实现可验证恢复前，结束菜单先不展示这个入口，不能做出点了也不能正确回来的空承诺。

## 十一 分工和实施顺序

1. 程序先实现新内容规则和画布账本，针对动作观察、阶段、撤销、终局互斥做相关领域测试；不运行归档旧主线作为新线通过证据。
2. UI按交接建立独立画布操作Prefab和假数据预览，先联调三笔可收、五六笔耗尽和最后一笔范围，再接入真实会话。
3. 关卡将新物件放在固定主画幅可见区，替换Visual并保留稳定Logic；输入许可和阶段显色同时配置。
4. TA先做底稿单区与刀刃单面原型，通过主视角可读性后再接全部区域；不先追求复杂屏幕后处理。
5. 音频补接触、翻页、短发现反馈；长诗和配音最后接，不能以语音解释掩盖交互不清。
6. 集成验证普通线和主动隐藏线，做真实构建UI检查及首次玩家测试。设计通过、自动化通过与真人理解通过分开记。

完成定义和具体测试矩阵见《06 问题闭环与验收计划》。没有相关领域改动的纯Prefab拆分，只做编译、引用审计、运行与Console检查，不逐项执行全套测试。

原稿对应约束：台词读《09 原稿台词与触发表》；图样以原始1.png至4.png为准，不从概念图反推笔刷。每阶段均在对应过场旁白结束后只增量显色真正可交互的物件；屋顶独立等待试刮许可及相关旁白，不随普通阶段显色。配方保留黑色＋锋利→粗犷、混乱＋夜色→肉身、现实＋星辰→当下；第二第三阶段最终笔刷组合是明确标注的缺项补全。

旧三次服从收束的兼容边界：新四阶段内容必须以新的明确完成条件接管流程，不能在第三个概念配方后加载旧反应而提前锁画布。新内容仍使用Neutral/Compliant/Deviant元数据和重复提交去重；配方统计仅作已发生解释的记录，新线的普通终局只由第四阶段三笔、最终刀面接触及玩家点击“完成绘画”共同许可。旧场景的规则表不随本轮设计改写。

| --- | --- | --- | --- |
| InspectObject | ObjectId | 对应实体被玩家亲点、当前可调查 | 去重记录物件及其可见初始观察；ObjectInspected/ObservationFound |
| InspectDetail | 来源ObjectId、DetailId | 物件已亲点，玩家选择细看或远近比较 | 记录该来源的细节；不发其他物件 |
| WashReleasePigment | 杯和画笔来源、接触动作序号 | 亲点来源已成立，笔尖在真实水面内 | 洗笔及蓝色/流动结果观察；ContactAccepted后消费同批发现 |
| TurnMirror | 手镜来源、离散角度 | 手镜已亲点，比较角度进入宽容区 | 一次翻转观察；可重复转动但不刷发现 |
| ScrapePalette | 板、刮刀、刀刃、有限路径 | 合法干色试区内达到有效接触阈值 | 刮板经验与可见木底；空白/洁净只作描述，不增加无配方灰词 |
| SpreadPalette | 板、刮刀、刀面、有限路径 | 合法软色区，已调查来源 | 刀面经验；不增加屋面许可 |
| IgniteLamp | 现有左灯、已划燃火柴、接触序号 | 玩家亲点左灯，火柴接触灯芯 | 点灯与温暖/明亮观察，异常成立；可见提醒由表现安排 |
| CombineMaterials | 本次全部2个ClueId | 精确匹配本阶段有限配方和必要证据 | 概念或笔刷；不产出实体；失败不扣材料；历史三元仅保留兼容 |
| CommitStroke | 层、笔刷、UV、角度、成本/大小步、笔触ID | 本层开放、图样一致、预算区间及输入有效 | 原子扣量并追加笔触，递增画布版本；StrokeCommitted |
| UndoLastStroke | 层、预期版本 | 当前未封层且有可撤一笔 | 删除最后笔并原量退款，清过期收色；StrokeUndone |
| FinishLayer | 层、预期版本 | 前三层至少三笔；第三层另查两种工具经验 | 记放弃余量、封层、推进阶段；LayerFinished/StageChanged |
| FinishCanvasSpread | 第四层版本、刀面路径 | 第四层至少三笔，有效接触已画颜料 | 记录该版本收色，不自动定稿；CanvasSpreadCompleted |
| ProbeRoof | 屋面来源、刀刃路径 | 已亲点屋面、第四层至少三笔、未终局 | 首次有限小孔与观察，普通路线仍可用 |
| ContinueRoofScrape | 试孔、刀刃路径 | 已小试、第四层仍至少三笔、新接触落在开口边缘 | 原子锁隐藏路线，禁用普通定稿；RoofRouteCommitted |
| DeliverCanvas | 第四层当前版本 | 至少三笔且该版本已收色、隐藏线未锁 | 原子接受普通终局；CanvasDelivered |
| EraseRoom | 已亲点房间、刀刃路径 | 隐藏线锁定，天空/接连笔迹/房间均亲点，接触合法墙面 | 房间擦开事实；RoomErased，导演只播放其结果 |

命令失败分为已执行、来源未调查、当前阶段不允许、预算/版本已变、接触无效、终局已锁等明确原因。来源缺失时引导回真实对象，预算已变时刷新预览，终局已锁时停止世界输入；不能把所有拒绝都显示成“似乎没什么联系”。这句只用于组合未成。

事件顺序为：核验命令→原子写入事实与画布数据→规则闭包→冻结只读快照→发布结果批次→刷新UI和世界表现→按优先级安排提示与旁白。即使音频关闭、旁白被打断或某段动画跳过，事实与预算也不变化。无新增事件时重建画面只恢复现状，不重播发现。

## 十四 物件身份和内容配置

既有身份复用`atelier.painting`、`atelier.brush`、`atelier.manuscript`、`atelier.matches`、`studio.cup`、`studio.window`、`studio.ceiling`、`studio.sky`、`studio.room`；点灯继续沿既有左灯的稳定绑定。不能把旧`atelier.trial`试纸身份偷偷改成新干颜料板，也不能把屋面观察当屋顶物件ID。石膏、手镜、已有碎片、蜡笔画、干颜料板和刮刀是新增来源，分别拟用`atelier.flow.plaster_bust`、`hand_mirror`、`mirror_shards`、`crayon_picture`、`dry_palette`、`palette_knife`（后五项同一前缀）。

每个物件的内容行至少包含：稳定ID、中文名、首次可用阶段、主视角拾取区、Visual引用、近景Pose、介绍词ID、初始观察ID、细节操作和反馈组。初始观察与动作结果分开，避免点杯就提前得到蓝色、点未燃灯就得到明亮。图样行包含PNG引用、有效Alpha矩形、面积标定、默认角度、预算100、计划笔数、全局成本12至24及本层完成前置。

旁白行包含N/O稳定键、原文、采用文本、触发条件、优先级、完整句分段、声音引用、一次性和回读方式。阶段行只引用当前合法对象、配方、图样和显色组，不复制其文本。编辑器内容校验需拒绝缺失PNG、空中文名、无机位的必要物件、不可行颜料预算、重复ID和配方产出物体等错误。
